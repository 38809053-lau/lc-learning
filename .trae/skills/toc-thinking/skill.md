# TOC清晰思考技能

## 触发词

用户说出以下任一表述时，触发此技能：
- "我陷入两难"
- "帮我分析冲突"
- "核心问题是什么"
- "TOC分析"
- 其他明确表示需要TOC思维帮助的场景

---

## 技能描述

基于TOC（制约理论）的五步思考流程，通过引导式对话帮助用户将复杂问题可视化、系统化地找到双赢解决方案。

**适用场景**：
- 长期存在的不良效应（业绩下滑、团队冲突、个人纠结）
- 需要双赢解决方案而非妥协的决策
- 复杂系统中寻找根本原因与突破点

---

## 五大设计原则

### 1. 串联确认门（核心约束）

**TOC逻辑链是串联的，前一步错则全盘错，绝不允许跳步。**

```
困境定义 ✗ → 中断，要求重新定义
     ↓
冲突图构建 ✗ → 中断，要求重新构建
     ↓
现状溯源 ✗ → 中断，要求重新分析
     ↓
双赢方案 ✗ → 中断，要求重新设计
     ↓
消除顾虑 ✗ → 中断，要求补充
     ↓
行动计划 ✗ → 中断，要求完善
```

**每次只推进一步，确认无误后进入下一步。**

---

### 2. 四种破解方法

每次必须穷举四种方法，由用户选择或组合：

| 方法 | 适用场景 | 核心问题 |
|------|----------|----------|
| **改变++** | 挑战D→C假设 | "D真的会导致C吗？有没有例外？" |
| **不改变++** | 挑战D'→B假设 | "D'真的无法满足B吗？如何优化？" |
| **何时改变** | 找出冲突条件 | "在什么条件下D和D'不冲突？" |
| **另一种改变** | 跳出D/D'框架 | "有没有第三条路同时满足B和C？" |

---

### 3. 说服顺序（严格禁止颠倒）

```
第一步：鳄鱼 → 第二步：金子 → 第三步：美人鱼 → 第四步：拐杖
```

**顺序逻辑**：
- 先说"改变的坏处"（鳄鱼）—— 诚实面对风险，建立信任
- 再说"改变的好处"（金子）—— 建立信心，激发动力
- 然后"不改变的好处"（美人鱼）—— 承认损失，减少阻力
- 最后"不改变的坏处"（拐杖）—— 打破幻想，推动行动

**禁忌**：先说好处再说坏处，这会让人产生防备心理。

---

### 4. 不妥协原则（写入核心约束）

**"找不到双赢"不是结论，是假设还没找全的信号。**

当用户说"没有别的办法"时，必须追问：
- "真的是这样吗？"
- "这个结论成立的前提是什么？"
- "前提本身可以被打破吗？"

**标准回复模板**：
> "冲突不可调和"本身就是一个需要被质疑的假设。TOC的原则是：只要B和C都是真实需求，就一定存在同时满足两者的方案。问题不在于"有没有"，而在于"还没找到"。让我们继续挖掘。

---

### 5. 文本图可视化（全程使用）

所有图表必须用纯文本ASCII格式，直接嵌入对话：

**冲突图模板**：
```
              [A]
             /   \
            /     \
         [B]       [C]
          \         /
           \       /
         [D]---X---[D']

  D   = 当前行为
  D'  = 相反行为
  B   = D满足的需求
  C   = D'满足的需求
  A   = 共同目标
  X   = 冲突点
```

**现状图模板**：
```
  [不良效应1] → [不良效应2] → [中间效应] → [核心问题]
      ↑              ↑            ↓
  [不良效应3] → [不良效应4] ────┘
```

**四象限模板**：
```
  ┌─────────────────┬─────────────────┐
  │   🐊 鳄鱼      │   🌟 金子      │
  │  (改变的坏处)  │  (改变的好处)   │
  ├─────────────────┼─────────────────┤
  │   🧜‍♀️ 美人鱼   │   🩺 拐杖      │
  │ (不改变的好处) │ (不改变的坏处) │
  └─────────────────┴─────────────────┘
```

## 五步流程详解

### 第一步：定义困境（确认门）

**目标**：清晰定义待解决的问题

**必须收集**：
- 问题是什么？（具体描述）
- 谁受到了影响？
- 持续多久了？
- 已经尝试过什么？

**确认门**：用户明确说"是的，这是我要解决的问题"后才能进入下一步。

---

### 第二步：冲突图构建（确认门）

**目标**：将困境转化为D-D'-B-C-A结构

**标准引导**：
```
请回答以下问题，帮助我构建冲突图：

1. 你当前采取的行为是什么？（D）
2. 与之相反的行为是什么？（D'）
3. D满足了什么需求？（B）
4. D'满足了什么需求？（C）
5. B和C的共同目标是什么？（A）
```

**冲突图验证**：
```
              [A]
             /   \
            /     \
         [B]       [C]
          \         /
           \       /
         [D]---X---[D']

检查：
✓ 逻辑链：为了A，必须B；为了B，必须D
✓ 逻辑链：为了A，必须C；为了C，必须D'
✓ 冲突点：D真的导致C吗？D'真的导致B缺失吗？
```

**确认门**：用户确认冲突图准确反映困境后才能进入下一步。

---

### 第三步：现状溯源（确认门）

**目标**：找出造成冲突的根本原因

**方法**：收集10-15个不良效应，用"如果...那么..."连接

**文本图输出**：
```
根据你的描述，不良效应链条如下：

  ┌─────────────────────────────────────────┐
  │  [效应1] → [效应2] → [效应3]           │
  │      ↓              ↓                  │
  │  [效应4] → [效应5] ───→ [核心问题]     │
  └─────────────────────────────────────────┘

根本原因：_____________
```

**确认门**：用户认同根本原因分析后才能进入下一步。

---

### 第四步：双赢方案（确认门）

**目标**：开发1-4个候选方案

**必须穷举的方法**：

1. **改变++**
   - 挑战D→C假设
   - 问："D不必然导致C的例外情况存在吗？"

2. **不改变++**
   - 挑战D'→B假设
   - 问："如何优化D'使其满足B？"

3. **何时改变**
   - 找出冲突条件
   - 问："在什么条件下D和D'可以共存？"

4. **另一种改变**
   - 跳出D/D'框架
   - 问："有没有第三条路同时满足B和C？"

**文本图输出**：
```
候选方案：

方案1 [改变++]：_____________
  关键假设：_____________
  假设挑战：_____________

方案2 [不改变++]：_____________
  关键假设：_____________
  假设挑战：_____________

...（至少列出所有适用的方法）
```

**确认门**：用户选择或组合方案后才能进入下一步。

---

### 第五步：消除顾虑（确认门）

**目标**：确保方案无重大隐患

**引导问题**：
1. "这个方案可能带来什么顾虑？"
2. "顾虑成立的前提是什么？"
3. "前提能被打破吗？"
4. "需要什么补充机制？"

**文本图输出**：
```
顾虑与对策：

🛡️ 顾虑1：_____________
   前提：_____________
   对策：_____________

🛡️ 顾虑2：_____________
   前提：_____________
   对策：_____________
```

**确认门**：用户确认顾虑已被充分消除后才能进入下一步。

---

### 第六步：说服与行动（最终门）

**目标**：制定可执行的行动计划

**说服顺序（严格禁止颠倒）**：

```
第一步：🐊 鳄鱼（改变的坏处）
第二步：🌟 金子（改变的好处）
第三步：🧜‍♀️ 美人鱼（不改变的好处）
第四步：🩺 拐杖（不改变的坏处）
```

**文本图输出**：
```
四象限分析：

┌─────────────────┬─────────────────┐
│  🐊 鳄鱼       │  🌟 金子        │
│  改变的坏处：   │  改变的好处：   │
│  1. ___________ │  1. ___________ │
│  2. ___________ │  2. ___________ │
├─────────────────┼─────────────────┤
│  🧜‍♀️ 美人鱼    │  🩺 拐杖        │
│  不改变的好处： │  不改变的坏处： │
│  1. ___________ │  1. ___________ │
│  2. ___________ │  2. ___________ │
└─────────────────┴─────────────────┘

行动承诺：
第一步：_____________
时间节点：_____________
衡量标准：_____________
```

## 禁忌清单

1. ❌ 不允许跳过任何确认门
2. ❌ 不允许只提供一种破解方法
3. ❌ 说服顺序禁止颠倒（必须鳄鱼→金子→美人鱼→拐杖）
4. ❌ 不允许说"找不到双赢方案"，必须继续挖掘假设
5. ❌ 不允许使用图片或外部工具，所有可视化必须是ASCII文本

## 沟通模板

**开始分析**：
> 好的，我来帮你用TOC思维分析这个问题。这是一个串联的分析过程，每一步都需要你的确认。请跟随我一步步来。

**确认门话术**：
> 请确认以上分析是否准确反映了你面临的情况？只有确认无误后，我们才能进入下一步。

**挑战假设话术**：
> "真的是这样吗？"
> "这个结论成立的前提是什么？"
> "前提本身可以被打破吗？"
> "有没有例外情况？"

**不妥协话术**：
> "冲突不可调和"本身就是一个需要被质疑的假设。只要B和C都是真实需求，就一定存在同时满足两者的方案。问题不在于"有没有"，而在于"还没找到"。

**推进话术**：
> 很好，这个冲突图已经准确反映了你的困境。让我们进入下一步：找出造成这个冲突的根本原因。
